# Журнал взаємодії зі ШІ (вайбкодинг) — ЛР № 5

Інструмент: Claude (Anthropic) у середовищі Claude Code з доступом до оболонки Linux, Node.js 22 і Chromium.
Роль розробника: сформулювати вимоги, затвердити архітектуру, перевірити результат тестами й вручну, ухвалити рішення про безпеку.

## Початкова специфікація
Нижче — специфікація, сформульована за вимогами методички (архітектура, API, модель даних). Це опис завдання для ШІ, а не дослівна копія всіх повідомлень сесії.

> Продовж проєкт ScentFromV із ЛР 1–4 (HTML/CSS/JS-клієнт, 25 сторінок). Додай сервер на Node.js, базу даних і REST API.
> **Архітектура:** клієнт → fetch/JSON → сервер → SQL → БД; клієнт роздається тим самим сервером.
> **Дані:** users, sessions, products, orders, order_items, messages.
> **API:** каталог (читання з фільтрами), CRUD товарів для адміністратора, реєстрація/вхід/профіль, створення й перегляд замовлень, форма контактів.
> **Вимоги безпеки:** валідація вхідних даних, хешування паролів, параметризовані запити, секрети в змінних середовища, ціни рахує сервер.
> **Приймання:** усі сценарії з ЛР 4 працюють через сервер; автотести API; помилки сервера не розкривають деталей; розгортання з README.

## Ризики ШІ-коду, що виявлені під час роботи
- Хибні припущення про середовище (наявність Express/npm) — виявлено перевіркою, а не прийнято на віру.
- Тест, що «проходить» через помилку в умові — виявлено при читанні тестів, а не лише результату запуску.
- Асинхронність: код, що працював синхронно з localStorage, потребував чекання відповіді сервера — перевірено e2e.
- Безпека не гарантується генерацією: окремо перевірено SQL-ін’єкції, path traversal, підміну ціни, доступ до чужих замовлень, перебір паролів.
